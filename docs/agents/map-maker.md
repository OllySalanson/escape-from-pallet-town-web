# The map maker

The map file format, MAKE A MAP, placement rules, review advice and areas (insides and caves). `docs/maker-areas.md` covers areas in depth.

Moved out of `AGENTS.md` on 9 Nov 2026 so that file stays small; nothing here was reworded. Keep it current the way `AGENTS.md` asks: a change that adds a subsystem or makes a note here untrue updates the note in the same change, and a new note goes in the doc whose area it belongs to.

## Notes

- **A map can be one file, and the game asks a list of maps rather than knowing five** (player map maker stage 1, 2026-10-03). `world/mapFile.ts` is the format - ground as rows of material letters plus Viridian City's stamps, Kanto buildings by the file's *own* names (`MAP_FILE_BUILDINGS`, so renaming a prop never breaks a published map), named drop-ins, exits with an `opens` field that locks and keys will extend, item spots (the game decides what is in them) and a habitat that picks one of the shipped wildlife tables; optionally people (a look from the townsfolk/trainer designs, never a named one), signs, landmarks (a kind that sets the payout, the `pois.ts` rule, never money), districts (rectangles, optional habitat) and trainers (a team that is one of the game's own measured toll trainers by id, `MAP_FILE_TRAINER_TEAMS` - makers never author a party) - and `readMapFile` is the shape check (`{ draft: true }` opens an unfinished draft) and hands back **only the format's own fields, at every depth** (`world/mapFileRebuild.ts`, the security review's M3: anything else in a file rode review, approval and publishing into the repo unseen) - and a name in a file picks out of one of the game's tables only with `Object.hasOwn` or `includes`, never `in`, which answers yes for `constructor` and `toString` (red team F1, `mapFilePrototypeNames.test.ts`) - a field added to any `MapFile*` type fails to compile until it is listed there, as a key added to `MapFile` does in `MAP_FILE_KEYS`. File content reaches the game through the same lookups as authored content: `entitiesForMap`, `poisForMap`, `districtsForMap`, `trainersOn` (`world/mapTrainers.ts`), and `districtEncounterTables(raidMapId)`, which adds only the raid's own file map. `world/playerMaps.ts` registers every `src/maps/player/*.json` (published: approved by the owner) and `src/maps/sample/*.json` (the sample) at build time, and takes a draft at run time (`registerPlayerMap`). A published map's front door is offered to every save that has banked the first contract (`availableInsertionIds`, `isPublishedMap`), listed under PLAYER MAPS with its maker credited; the sample is only ever reached through the explorer run. No name or line in a map file may hold `< > & "` (`UNSAFE_TEXT`), which is what keeps player text safe on every DOM screen without each one escaping it, and beyond printable ASCII only the accented Latin and punctuation the typeface draws (`world/mapText.ts`, the owner's call on playtest 19: no emoji or right-to-left scripts yet, nothing invisible); the editor takes anything else out as it is typed and says so (`MapMakerScene.refuseUnwrittenText`), and `placeSlug` folds accents so `Café` and `Cafe` are one place. A drop-in's insertion id is `dropInKey` - its optional kept `id`, else its name's slug - so a published fix can rename one without losing a landing a player reached. A file map's id is `player-<id>` (`PlayerMapId`), so `WorldMapId = BuiltInMapId | PlayerMapId`: a table authored for the shipped five is keyed by `BuiltInMapId`, and anything that answers for whatever map a raid is on asks `worldMapIds()`, `getWorldMap()`, `worldMapName()`, `runInsertions()`/`runInsertion()`/`insertionsOn()` and `extractionPointsOn()` instead of indexing `WORLD_MAPS`, `RUN_INSERTIONS`, `EXTRACTION_POINTS` or `WORLD_MAP_NAMES` (which stay as the shipped maps' authored tables). `generateRunPlan` builds every shipped map plus only the raid's own file map, so adding maps never moves a roll of a shipped raid (`mapFile.test.ts` holds that). Whether a map *works* is `world/mapFileChecks.ts` - stands on ground, nothing shares a tile, every drop-in walks out in the clock (townsfolk and signs counted as walls), everything reachable, room for the hunter, no trainer watching a drop-in or exit, and every name and line passing `world/wordFilter.ts` - and every bundled file is held to it. A bundled file that does not load (an old format, an id already taken, an id in `RESERVED_MAP_FILE_IDS` such as `try-it`) is **left out, never thrown**: `loadBundledMaps` in `playerMaps.ts` skips it and `playerMapProblems()` names it, so one map cannot stop the game starting, while `mapFile.test.ts` fails on any problem so the change that broke a file has to mend it. `tools/tileset/renderMap.mts -- player-<id>` draws one. **The suite always runs with one approved map in the game** (`world/publishedMapFixture.testkit.ts`, loaded by `vitest.config.ts`), because the publish workflow runs it with the new map in `src/maps/player/`: a test may never count the shipped maps, so ask `deployableMapIds()`, `frontDoorFor()`, `extractionPointsOn()` and `insertionsOn()` rather than `EVERY_FRONT_DOOR`, `RUN_INSERTIONS` or a literal number of board rows.
- **The map maker is MAKE A MAP on the title, and a map in it is only ever the file it will save** (a new map is named by `maker/mapNames.ts` in the world's own words - place-words of the shipped maps, a little grit, Kanto Pokémon, the trades that work the land - with REROLL beside the field and every name the generator can make held to the word filter and the map-name rules) (stage 2 of the player map maker). `scenes/MapMakerScene.ts` hosts a pixel-ui screen (`maker/makerView.ts`, pure markup); every edit is a new `MapFile` through the pure functions in `maker/draft.ts` (paint with a `maker/palette.ts` brush, fill, rectangle, place/move/remove, rename, resize - a ledge is painted as runs and `joinLedges` gives every row its ends), so undo is a list of files (`maker/history.ts`), the checks are `checkMapFile` of what is on screen, and the picture is the game's own `buildMapLayers` drawn onto a canvas (`maker/mapCanvas.ts`) that is **kept, never repainted**: `maker/mapPainter.ts` redraws only the tiles a new version can look different on, and `maker/layerPatch.ts` rebuilds the layers of a changed patch from a crop, because no tile's art is decided by anything more than `PATCH_REACH` away (`layerPatch.test.ts` holds patched to whole over random edits). Rebuilt whole, one brush step on a 128x128 map cost 270 ms; patched it is under a millisecond at 256x256, the cap (`MAP_FILE_LIMITS`, four times the Floodplain) - `tools/playtest/makerHuge.mjs` measures it and checks the kept picture against one drawn whole, pixel for pixel. **A map grows by drawing past its edge**: the window draws the room the map may still grow into (`growthRoom`, `stackLayout`), and Brush, Box, Place and a Select drag there call `growToFit`, which lays wood round the old map (`extendMap`) with a whole tree past what was drawn - west and north **two tiles at a time**, because the lattice and the grass weave are laid on even rows and columns and an odd shift redraws every tree. Everything on the map moves with its ground through `shiftThings`, whose table names every key of `MapFile`, so a new part of the format does not compile until it says whether it moves. The painter keeps the old picture moved (`MapPainter.grew`), the window is held on what it showed (`holdingTheView`, undo and redo included) and `tools/playtest/makerGrow.mjs` plays all of it. Round a huge map: Ctrl and the wheel zoom about the pointer, the middle button or Space held moves it (Space is taken over the map before `overlayKeyboard` can press the focused tool with it), and `maker/overview.ts` is the drop-in screen's own minimap in the window's corner (`tools/playtest/makerNav.mjs`). Drafts live in `localStorage` under their own key (`maker/drafts.ts`), never in a save, and a draft is never dropped: one with things off the map is opened without them (`keepOnMap`, which `resizeMap` also ends in), and one that still cannot be read is kept as stored in `MakerStore.unreadable` and written back by every save. Autosave is a throttle flushed on `pagehide`, a text field is saved as it is typed and commits against the thing it was drawn for, and `tools/playtest/makerDataLoss.mjs` plays every one of those losses end to end. Undo history and the view (zoom, scroll) are kept per draft for the page's life (`sessionHistories`/`sessionViews` in `MapMakerScene.ts`), so a TRY IT or a trip to the title costs neither; Escape drops a stroke, then the choice, then a panel, and never leaves - TITLE does. `render` writes the whole screen, so every list comes back at its top unless it is put back: the paint list keeps its scroll while it shows the same place's tools and a side panel's list while it is the same panel (`shownLists`), and a new thing put down takes the list choices last made for its kind - which Pokémon, look, berry, team (`REMEMBERED_CHOICES`, `chosenFor`). A choice is an index into a list, so every removal commits with the choice explicitly cleared (`commit` has no default for it) and `render` drops one `thingExists` says is gone. A stroke is held to the part of the map in view (`visibleTileAt`) and the window scrolls on while it is held past an edge, rather than painting ground out of sight; `MapMakerScene.test.ts` is the scene's own harness. **TRY IT** (`maker/tryIt.ts`) registers the draft as the map `player-try-it`, deploys the three starters (each evolved as far as its level reaches) at a level the maker picks beside WALK IT / RAID IT - starting on `suitedTryLevel`, the highest level anything on the map fights at, kept per draft for the page's life - onto it in a third save slot (`TRY_IT_SAVE_KEY`, `SaveSlot` `'try-it'`) so a try can never touch the game or the explorer run, and every raid ending goes through `homeAfterRaid()` back to the maker; WALK IT plays under the explorer rules (`setTryItRules`, read by `isPlaytestRun()`) but with no hunter (`hunterComes()`, the calm walk its help line promises), RAID IT under the game's. Leaving by an exit records `walkedVersion(file)` on the draft - a fingerprint of the whole file less its words (`WORDING` in `drafts.ts`), so a rename keeps the tick and a trainer, boulder or inside added takes it away - which is the seventh check; Escape in a try asks, then goes back to the maker without the tick (`LEAVE_TRY_PROMPT`). PLAYTEST sits beside MAKE A MAP on the title, half a row each, because four full-width rows do not fit 320x240. **What a maker can plant is a word in `MAP_FILE_BUILDINGS`** (`mapFile.ts`, the file's own vocabulary, never a prop name) drawn from `PLAYER_MAP_TILESET` (`tileset/playerMapTileset.ts`: the Kanto catalogue plus the base sheet's shed and blue cottage and the Floodplain's CC0 objects, which the captain asked for on 2026-10-10 - "as much stuff in the map maker as possible"), listed by `BUILDING_CHOICES` under `PLANT_GROUPS` with a picture of each drawn whole by `drawPlantSwatch` - each group a fold, shut until the maker opens it and kept for the page's life (playtest 48 #2: one list was 174 rows and the Cave mouth 4,200 px down), so a playtest driver opens them first with `OPEN_PLANT_FOLDS` (`tools/playtest/browser.mjs`); `palette.test.ts` holds that every word is offered once and every one plants, saves and loads. Adding a thing is a word, a choice row and nothing else. A Nature, Town or Things piece without a door is planted along a drag as ground is painted (`plantsAlong` in `palette.ts`, `MapMakerScene.plantAt`): every tile crossed is tried, a piece that would overlap is skipped, so a row is spaced by the piece's own footprint, and the stroke is one undo step. A file's **doors** (`MapFile.doors`: a one-tile Cut tree, a one-tile Rock Smash rock - `rock-smash` is the third `FIELD_MOVE_IDS` entry, opened by the HM06 Bill already barters - or a dragged rectangle of Surf water) are the game's own field-move gates, built by `fileDoorGates` and added to `gatesForMap` the way a file's districts are added to `districtsForMap`; its painted **ledges** are one-way hops (`fileLedges`, one per row of ledge, never landing on a drop-in or an exit) added to `ledgesForMap`, and `mapFileChecks` walks them as a player can (drop-in walks and reachability hop, the hunter's room does not) and refuses a ledge a drop-in can reach whose landing has no way out or is in a trainer's watch - `world/ledges.ts`'s own rules; a district may carry `rain`. `mapFileChecks` walks the way out with every door shut (a raid must be leavable without Cut or Surf) and asks what can be reached with them open. Three more things a maker places are figures rather than tiles, so they can change during a raid without touching the map's collision: a **berry tree** (`MapFile.berryTrees`, `world/berries.ts` - Emerald's own trees cut from pret/pokeemerald by `scripts/cut-emerald-berry-trees.mjs`, because FireRed has none, each hung with one of seven berries that are ordinary FireRed medicine items) is picked once a raid by facing it (`WorldScene.pickBerry`, `ActiveRunSession.berriesPicked`); a **Strength boulder** (`MapFile.boulders`, `world/boulders.ts`) is pushed a tile by walking into it with a Pokemon that knows Strength, where it stands this raid riding on `ActiveRunSession.bouldersMoved` and read through `WorldScene.entityHolds`, so the hunter's search meets it as it meets a person - and it never comes to rest on anything a raid is for, nor where it would shut the player off from every exit (`canStillReach`); and an exit may `open` when **dug** (`ExtractionRequirement` `dug`): rubble, and a wall, until somebody faces it with a Pickaxe in the pack (`WorldScene.tryDigAt`, `ActiveRunSession.exitsDug`), for that raid only - the Pickaxe is a repeating Bill barter because it is lost with the pack. `mapFileChecks` walks the way out with every boulder standing and no buried exit counted (nobody has to bring Strength or a Pickaxe to leave) and asks what can be reached with the boulders moved aside. An item spot may be `hidden` (a fact about the place, so it survives every roll of what is in it): `WorldScene.createLoot` draws nothing for it, and it is found by stepping on it or pressing the interact key at it, as FireRed hides an item in a tile. A placed Pokemon with a `level` fights once a raid when spoken to: its cry, then a wild battle (`WorldScene.meetPokemon`, through the same dialogue-then-fight path a trainer uses), and `ActiveRunSession.pokemonMet` keeps it off every rebuild of the world for the rest of the raid, whatever the fight's ending. **More FireRed art comes from pret/pokefirered now, not The Spriters Resource**, which answers any automated fetch with a browser challenge: `scripts/cut-frlg-towns.mjs` draws Kanto's towns from their own metatiles and cuts buildings and field objects onto `frlg-towns.png` (`tileset/townSheet.ts`, generated `townPieces.ts` with a drawn/empty mask per cell), and `scripts/cut-frlg-people.mjs` cuts more looks into `characters/`. Both take a sparse pret checkout at commit `037335f`; nothing from pret is committed. `cut-frlg-towns.mjs --dump=<town>:<out.png>` writes a town or route whole with its block grid, which is how a piece's rectangle is read; a piece drawn over something it stands against (Route 10's Power Plant and its cliff) is cut `behind` it, lifting what matches that thing drawn alone. Lifting a building off its town is the hard part and the script's comments say why each rule is what it is: ground is a town's common walkable cell (a rooftop is walkable too, nobody can reach it), a crown over a roof is left out by its 8x8 tiles (the shared tileset's solid cells on the map's outer ring), and counting how often a cell is used can never tell a tree from a Gym roof. A file's **Pokemon** (`MapFile.pokemon`: any of the game's 151, `pokemonFigures.ts`) are `WorldEntity`s with `pokemon` set, drawn by `WorldScene.createPokemonFigure` from FireRed's two-frame party icons (`pokemon-icons.png`, cut by `scripts/cut-frlg-pokemon-icons.mjs`, feet on the tile's last row by each species' own sole), solid as a person and saying their own name to their own cry (`WorldScene.tryInteract`, the sample fetched as the figure is stood up); `maker/pokemon.test.ts` holds the icon list to exactly the game's species. The CC0 doors and hatches (mine mouth, culvert, cellar doors, trapdoors) are left out because they promise an inside, and insides are the maker's areas work.
- **The map maker refuses what it can already see is wrong, at the click, rather than reporting it later** (the captain, 2026-10-12: a Gym dropped on a block of trees came out with tips through its roof, half-trees round it and its door onto a wood). `maker/placement.ts` is the whole rule, its header the design: every piece has a footprint (cells it draws and stands on), an overhang (crowns, walked-under spans - a broadleaf's brim decides nothing) and doorsteps; one thing to a tile, and a crown hangs over nothing but ground, which is what keeps the canopy layer's draw order right. **Soft gives way to bigger**: growth (wood, hedge, bush) is cleared from under anything planted, clutter pieces (Nature, Things) from under a building, a wood a whole lattice tree at a time and the trees whose tips would hang over a building's wall with it, as one undo step - and a building carried away or taken off gives that clearing back where nothing has come to stand on it since (`regrowCleared`; the clearing is remembered per building object for the session, in `draft.ts`, never saved); hard things (buildings, Town and Signs structures, every spot, field-move doors, doorsteps, water, rock, fence, wall and ledge) refuse, every one of them named. Only water pieces stand in water and a cave mouth only in a rock face. Nothing may be boxed in: a spot needs a standable side, a placement that would take the last one is refused, and a stroke (`paintAround`) skips the tiles it may not touch and says why once. `draft.ts`'s place and move functions ask it and the ghost (`maker/ghost.ts`, drawn with the piece's own art by `drawPieceArt`) asks the same plan before the click, so the two cannot disagree; ground grown to hold a placement past the edge is the placement's (`clearGrownWood`). `buildMapLayers` counts lattice wood under a planted footprint as gone (no half-trees, no tips through a roof), which changes nothing on a shipped map - only maps drawn before these rules. The checks stay, because a file from elsewhere can still fail them, and every fault carries its tiles (`MapCheck.faults`): the list groups a run of one kind with a count and a chip per tile, and a click or Enter takes the maker there - the inside it is in, at least 1x, centred, chosen and flashed (`MapMakerScene.goToFault`, again for a fault's next tile). `tools/playtest/makerCollisions.mjs` plays every pair in the real maker (`--before` for an older build) and `makerCollisionSheets.mjs` composes the before/after sheets in `docs/screens/maker-collisions/`.
- **Review is told, never ruled** (the captain, 2026-10-11, playtest 12's owner call): a player map gets no fairness or economy check beyond does-it-work, and `world/mapFileSummary.ts` puts the facts a fair map and a cheat map differ on in front of the reviewer instead - the fewest trainers in a row on the way out from the worst drop-in, with the chance a lone Lv 12 starter and three Potions gets through them played as one carried-over series (`trainerMeasure.playTrainerSeries`), steps to the nearest exit, the pickups and the materials and money they pay (and how many lie within `NEAR_STEPS` of a drop-in), the nearest-thing walk `density.mts` measures the shipped maps by (`world/nearestThing.ts`; the quoted `SHIPPED_DENSITY` is held to the maps by `shippedDensity.test.ts`), and EMPTY. One line on every review row, all of it in the open map's pane, as advice: nothing in it may refuse or grey out a map. And the maker is a **mouse tool** and says so under its tools (`MOUSE_NOTE`, playtest 27's owner call): there is no keyboard drawing, and its tool, undo and zoom keys stay.
- **A player's map is several places in one grid, joined by doors** (`docs/maker-areas.md`). A file may carry `areas` (an inside: id, name, `style` - which FireRed room its floor and walls are - its own size, ground and `buildings`, which are its furniture, `MAP_FILE_FURNITURE`) and `links` (two ends, each a landing tile, the way you press - `toward` - and a `look`); everything placed carries an optional `area`, absent is outdoors, so every older file means what it meant. A building's door is the `door` look on the tile in front of its door cell (`MAP_FILE_BUILDING_DOORS`, `doorFront`); linking it opens the door. **You go through by pressing into the doorway from its landing and come out on the other landing facing away** - FireRed's own door mat rule - which makes every link symmetric, so `buildPlayerMap` lays the outdoors at the origin and each area east of it with solid dark between (`world/mapAreas.ts`, `composeMapFile`) and a player map is still one `WorldMapDefinition` (`areas`, `links`, and a `push` warp each way) - built per gate state like any map, because the file's Cut trees and Surf water (its `doors`, outdoors only) are laid by `composeMapFile(file, opened)` on the outdoors before the insides are packed beside it. Every search reads the links through `GridBounds.links` (`linkTable` in `movement/gridMovement.ts`; `throughLinks` in `hunter.ts`, the optional `links` of `stepDistances`), so the hunter, the checks, run generation and the standing board all walk through doors and an inside is never a safe box; pass `map.links` to any new walk over a map. `WorldScene` frames the area the player is in on black (`frameArea`, `AREA_DARK_DEPTH`), seats captions only over it (`captionGround`), surveys only it, names doors by where they lead (`createDoorwayLabels`), points headings at the door to take (`world/areaRoutes.ts`), and goes through with `walkThrough` - a fade, nothing rebuilt. The drop-in picture is the outdoors only. The checks add `doors` and `areas`, asked only of a map that has an inside. In the maker an area is edited as a **focused view** (`maker/areas.ts`: `focusArea`/`withFocusedArea`), a map file of its own that every `draft.ts` function works on unchanged, merged back keeping every list's order; GO INSIDE (`makeInside`) makes a room from the FireRed template the building is and links its door, a building moved or removed carries its inside with it, and the mat is dragged along its south wall. Insides are drawn from `frlg-areas.png`, cut from pret's FireRed disassembly by `scripts/cut-frlg-areas.mjs` (pinned commit, room + metatile + **layer** per piece; `areaSheet.ts`, `insideTileset.ts`): FireRed keeps a room's floor in a metatile's bottom layer and its furniture in the top layer, so top-layer pieces stand on any floor, while a piece drawn with both layers (a Mart fixture, a rug, a staircase, and every piece the base cut from its renders) keeps its room's floor and is offered only in that style (`furnitureFor`). A house can have an upstairs (`addUpstairs`): FireRed's stair warp is the little rug beside the stairs - west of a way up, east of a way down, the same tile on both floors (`stairsAt`) - and a FireRed house floor is shaded down its west side, which is the room's own edge (`MaterialTiles.edgesAtMapEdge`). `tools/playtest/makerAreas.mjs` plays the whole of it, and `tools/tileset/renderMap.mts --file=` draws a map file from disk with its insides. Drawing past the outdoors' edge grows the map (#232): the outdoor end of each link moves with the ground (`SHIFTS.links` in `maker/draft.ts`), a thing in an inside never moves (`moved` skips anything with an `area`), and an inside does not grow - it is the size its own fields say (`MapMakerScene.roomOf`). **A cave is an area of kind `cave`** (style `cave`: Mt. Moon's own floor `P`, rock `B` and sand `d`, cut from `MtMoon_1F`/`B1F`, up to 64x64). Its rock is an *overlay*, so its faces stand on floor or sand alike, and an overlay reads its diagonals where its art has an inside corner (the joints in a room's corners) while `edgesAtMapEdge: false` carries it on past the map's edge; the sand `joins` the rock. Its ways through are `cave-exit` (daylight cut into its south wall, rock either side), `ladder-up` (stood on at its foot) and `ladder-down` (a hole walked up to), and its mouth outdoors is the `cave-mouth` building, all door, which the checks hold to the foot of a rock face and to leading into a cave. A cave's floor rolls the `cave` habitat on every step (`WorldScene`, `currentArea().kind`). MAKE ITS CAVE, ADD A FLOOR BELOW (`addFloorBelow`) and the two-click passage (`maker/passages.ts`: an entrance, then where it comes out; a chosen way through names its other end and goes there, and two ends in one place are joined by a dotted line) make them, and `tools/playtest/makerCaves.mjs` plays the lot. A list of placed things added to the format belongs in `PLACED` (`maker/areas.ts`), or it shows in every place's view: `areas.test.ts` makes the compiler name every field of a file. **Every building with a door can have an inside, and a way through is as wide as FireRed draws it.** Kanto's town buildings open where FireRed's own maps put their doors: `scripts/cut-frlg-towns.mjs` reads each town's warps (`data/maps/<Town>/map.json`) into `TOWN_PIECES[...].doors`, in the piece's trimmed cells, and `MAP_FILE_BUILDING_DOORS` takes the bottom row's run as the front door (`MapFileBuildingDoor`: a cell and a width; the pier and Saffron's gate are not doors into rooms), the step drawn in front of one is walked (`frontSteps` in `townSheet.ts`), and each opens into the room it is (`templateFor`: Gyms and the Dojo into the gym hall, the Department Store and the Bike Shop into a shop, the Museum, labs and the Mansion into Oak's Lab, a landmark's inside named for it). Every cell of a wide door leads in (`landingsOf`), and a mat - three tiles of art - leads out from its middle tile only, as FireRed's do: **a FireRed warp fires only on a floor whose behaviour says it is one** (`src/field_control_avatar.c`), and the warps FireRed lays beside a mat's middle are on plain floor, so the cutter records only the ones that fire and how each is gone through (`door`, or the way an arrow warp is pressed). Ends as wide as each other pair tile for tile, otherwise the extra tiles lead to the other end's own tile, one way. **A building's doors are a list, each pressed its own way** (`MapFileBuildingDoor.toward`; `buildingDoorways`, `buildingDoorAt`, `doorEnds`, `linksThroughDoors`): a gatehouse - Route 2's and Saffron's north to south, Saffron's west to east, all cut by the town cutter, whose `warpsFrom` reads a gatehouse's far side off the map beyond it and whose `scrub` lifts the path off the cells it is walked onto from - has two, and its template (`ways`) puts a way out on each side of its room: a `back-door` in the back wall, or a `mat` let into a side wall (`toward` `left`/`right`, drawn over the dark beside it by `insideSideMat`). The ridge and porch roofs are `walkedUnder` canopy in `townSheet.ts`, so a player stands behind them as in FireRed. A room's ground may hold `C`, the dark beyond its walls: drawn as nothing, solid. **A floor of Lavender Town's Pokemon Tower is a fourth kind, `tower`** (style `tower`, `TOWER_SIZE`, its ground `TOWER_GROUND`): the round room woven cell for cell as the tunnel below is, stairs up let into its east edge and down into its west (`towerStairs`), its mat at the foot of the ground floor, graves and statues as furniture; it keeps the Bicycle out and rolls for wildlife on every step only where a district on it names its wildlife (`stepRolls`), as FireRed's upper floors do and its ground floor does not, and the maker's Pokemon Tower opens onto one. The tower's graves stand outdoors too (`grave`, `gold-grave`, `grave-statue`), FireRed's own where the CC0 `gravestone` is not. **The Underground Path is a third kind of area, `tunnel`**, FireRed's own north-south tunnel at FireRed's own size (`TUNNEL_SIZE`, fixed by `areaLimits`) because its floor and walls are **woven**: the room cutter's `WEAVES` writes the game's own grid of floor and wall metatiles into `AREA_WEAVES`, and the `underground` style lays both by `MaterialTiles.weave`, each joining the other so neither draws an edge - a new style that must match FireRed cell for cell can be laid the same way. `makeUndergroundPath` makes the whole of it from two huts (both entrances, the tunnel, a `stairwell` down in each entrance linked to the `tunnel-stairs` at the end nearer it), started from a hut's pane and finished by clicking the other hut, through the passage tool's `path-hut`. A doorway's caption names the whole of its art as well as its tiles, so it is seated beside a stairwell rather than looking for a seat inside it. **The searches walk only links that go both ways** (`ComposedDoorway.twoWay`, `searchedLinks`): the hunter's downhill walk over a distance field breaks on a one-way edge, so a one-way tile is a way out for a player and nothing more; only an end's own tile is captioned (`MapWarp.secondary`). `tools/playtest/makerBuildings.mjs` walks in by the Bike Shop's right-hand door cell and out by its mat's left-hand tile.
